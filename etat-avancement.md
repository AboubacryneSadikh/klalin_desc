- Paramètres : Tarification, CORS (domaines autorisés), Messagerie (canaux e-mail/SMS), **Rôles & permissions** (`pages/parametres/roles/`), **Utilisateurs & rôles** (`pages/parametres/utilisateurs/`) — liste les comptes, permet d'affecter/retirer un rôle, **de créer un compte** (formulaire inline nom/prénom/canal/identifiant/rôle) et **de bloquer/débloquer** un compte (désactivé sur soi-même), et **Journal d'audit** (`pages/parametres/audit/`) — table paginée filtrable par module/plage de dates sur `GET /api/audit` — toutes accessibles depuis le menu Paramètres
- **URL de l'API** : plus aucun `http://localhost:8080` codé en dur dans les services/l'intercepteur — vient de `environment.apiUrl` (`environment.development.ts` et `environment.ts` (prod) pointent tous deux sur `http://localhost:8080` en attendant un vrai déploiement de l'API)
- **Guards de permission** (`core/guards/permission.guard.ts`) : `AuthService` décode les claims `permissions` et `sub` du JWT et expose `aPermission(module, permission)`/`utilisateurId()` ; `permissionGuard(module, permission)` bloque l'accès à une route (redirige vers `/acces-refuse`) si le droit manque — posé en plus de `authGuard`, jamais à sa place, la vérification qui compte reste côté API. Appliqué sur `/polices`, `/polices/nouvelle`, `/parametres/tarification|messagerie|domaines-autorises|roles|utilisateurs`. Le menu Paramètres masque les entrées sans droit ; les boutons d'action se masquent/désactivent pareil
- **Création de police** (`pages/polices/police-create/`) : le champ "ID Client" (saisie manuelle d'un id numérique) a été remplacé par un choix Client existant (recherche débouncée sur `core/services/souscripteur.service.ts`, résultats cliquables ≥44px pour l'usage tactile terrain) / Nouveau client (sous-formulaire inline civilité/nom/prénom/ville/email/téléphone), gaté par les permissions `CLIENTS:LECTURE`/`CREATION`. Les listes/détails de polices affichent le nom du souscripteur au lieu d'un id brut. Le formulaire reste dans les primitives `.form-grid.cols-2` déjà mobile-first (`_forms.scss` : 1 colonne <640px, 2 colonnes ≥640px) — aucun retrofit responsive n'a été nécessaire pour l'usage agent terrain sur mobile

## Codé (`klalin-client-portail`, Angular, nouveau)
Application séparée (pas une section du backoffice), sibling de `klalin-backoffice-portail`, même API/JWT (`AuthService` générique copié-adapté, aucune inscription — comptes provisionnés automatiquement uniquement). PWA via le schematic officiel `@angular/pwa` (service worker + `public/manifest.webmanifest`, `theme_color`/icônes de marque) — base commune prévue avec une future appli mobile.
